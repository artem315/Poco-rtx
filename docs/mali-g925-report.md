# Проверка шейдеров PocoRTX под GPU POCO X8 Pro Max

Все фрагментные шейдеры мода скомпилированы **Arm Mali Offline Compiler v2026.3.0**
(драйвер Mali **r56p0**) под **Immortalis-G925** — GPU POCO X8 Pro Max — в том виде,
в каком их получает драйвер телефона:

- для 1.20.1 / 1.21.1 — как GLSL ES 3.00 по двум путям Android-трансляторов
  (прямая замена `#version 150` → `#version 300 es` и GLSL → SPIR-V → ESSL,
  как делает MobileGlues);
- для 26.2 / 26.3 — как SPIR-V для Vulkan-бэкенда игры и как ESSL для GL-бэкенда.

Результат: **все 26 вариантов компилируются без ошибок, ни в одном нет вытеснения
регистров в стек** (stack spilling).

Отдельно все шейдеры прогнаны через **настоящий конвертер LTW** — основного рендерера
MJ Launcher (см. раздел [«LTW»](#ltw--основной-рендерер-mj-launcher) ниже). Это нашло
три проблемы, которых не видно при простой компиляции; все три исправлены.

Такты — «самый длинный путь» на один пиксель: A — арифметика, T — текстуры.
Для двух Vulkan-шейдеров компилятор не считает самый длинный путь (число итераций
циклов приходит из uniform-буфера), там указано «—»; та же логика в GLES-варианте
посчитана в соседних строках.

## LTW — основной рендерер MJ Launcher

LTW собран из исходников (тот же код, что в MojoLauncher) и запущен на Linux. Его
конвертер шейдеров получал ровно то, что игра передаёт в `glShaderSource`:

- 1.20.1 / 1.21.1 — шейдеры мода с подставленными `#moj_import`;
- 26.2 — GLSL 330 с define'ами, как его собирает игра;
- 26.3 — SPIR-V → GLSL 330 через SPIRV-Cross с теми же настройками, что в
  `GlPipelineRecompiler` игры.

Результат LTW (ESSL 3.20) проверен glslang и скомпилирован Mali Offline Compiler под
Immortalis-G925. Найдено и исправлено:

1. **Точность глубины.** LTW объявляет все `sampler2D` как `lowp`, если в шейдере нет
   `sampler2DShadow`. На Mali такая выборка возвращает 16-битное число (fp16), а
   глубина около 1.0 в fp16 теряет почти все знаки: тени, AO и отражения сломались бы.
   Исправление: в шейдеры, которые читают глубину напрямую, добавлен служебный
   `sampler2DShadow`, который никогда не читается (ветка с заведомо ложным условием от
   uniform). Увидев его, LTW объявляет `highp sampler2D`. В 1.20.1 / 1.21.1 это проход
   pack. Остальные проходы читают упакованную 8-битную глубину, которая переживает fp16
   без потерь. В 26.2 / 26.3 это отдельные варианты всех четырёх проходов, только для
   OpenGL-бэкенда; Vulkan-пайплайны не изменились.
2. **Константы.** LTW печатает числа с плавающей точкой с 7 значащими цифрами:
   `16777215.0` превращалось в `1.677722e+07`, и 24-битная упаковка глубины в 1.x
   давала мусор. Упаковка переписана на маленькие константы (255 и 256).
3. **26.3 на OpenGL.** SPIRV-Cross превращает векторный `?:` в `bvec3(cond)`, а
   принтер LTW выдаёт из этого присваивание `bool` в `bvec3` — проход освещения не
   компилировался бы, и мод отключился бы. Выбор переписан через `mix`/`step`.

## Оценка нагрузки на кадр

Экран 2772×1280, GPU 12 ядер до 1.6 ГГц (по данным POCO). Оценка = пиксели × такты
самого длинного пути / (ядра × частота), то есть **худший случай**: все циклы до
максимума, каждый пиксель по самому дорогому пути. Пропускная способность памяти не учтена.

| Качество | Версия | 1.6 ГГц | 1.0 ГГц (троттлинг) |
|---|---|---|---|
| Среднее (по умолчанию) | 1.20.1 / 1.21.1 | 4.3 мс | 7.0 мс |
| Среднее (по умолчанию) | 26.x | 3.3 мс | 5.3 мс |
| Ультра | 1.20.1 / 1.21.1 | 15.4 мс | 24.6 мс |
| Ультра | 26.x | 11.9 мс | 19.0 мс |

Для 60 FPS бюджет кадра 16.7 мс, поэтому «Среднее» (по умолчанию) и «Высокое»
укладываются с запасом, а «Ультра» на телефоне не рекомендуется.

Повторить: `malioc -c Immortalis-G925 --opengles <shader>.frag` или
`malioc -c Immortalis-G925 --vulkan <shader>.frag.spv`.
